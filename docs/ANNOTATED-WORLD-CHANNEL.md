## Editorial direction
World knowledge in the original English: intellectual argument, literary passage, science or history; the actual idea comes first. Japanese context/annotations deepen understanding rather than paraphrase. Pilot 013 is a user-approved visual baseline, not automatic approval of later clips. Start with a small batch of individually reviewed works (e.g. 3–5, no forced daily quota). Reject if not clearly compelling, original source meaning/translation uncertain, notes merely repeat, hook cannot be fulfilled, typography or audio awkward, or rights unclear. Check English/Japanese voice separation, every caption, mobile first frame/whole film, intelligibility and mix, attribution and links. Do not upload alternative hooks as near-duplicates to the public feed. For synthetic readings, use the reviewed The Annotated World site content and inherit its documented provenance. Verify the actual original recording separately only when using original audio. Independently review quote scope, rights and final media before approval. No synthetic voice deception or fabricated sources. No promised recommendation recovery.

## Publication workflow (reusable from episode 002 onward)

**One standard path, not a new one-off script/PR for every video.** The source of truth is `nomuonji/The-Annotated-World/productions/<clip-id>/brief.json` and `status.json`. The owner can authorize publication by saying "この動画を投稿して" in chat; the publishing agent records this episode-specific permission once in `status.ownerAuthorization`. Do not ask again for the same release. Authorization for episode 001 is **not** blanket approval of all future clips.

1. **Site → script:** start from the existing site article's frozen English text and chapter blobs, translation, context and commentary. Do not re-download the original lecture for synthetic narration. Preserve any `transcriptProvenance: unverified` history and do not describe synthetic reading as the person's original audio.
2. **Render once:** choose a properly licensed TTS voice and visual/music materials; save the final Kokoro cue-level brief in the source repo **before** marking `script.renderMatchesBrief:true`. Upload the finished MP4, SRT, contact sheet, timeline, report and (where relevant) voice-only WAV in a successful GitHub Actions artifact. Record `render.sha256`, exact `render.artifactUrl` (`https://github.com/nomuonji/The-Annotated-World/actions/runs/<run-id>/artifacts/<artifact-id>`), `render.renderMatchesBrief:true`. The artifact may expire: it must remain available until distribution.
3. **Review evidence:** for a new clip, invoke `/aw-audit <clip-id>` on owner Issue #31 (or Actions → Annotated World local speech QA) to run CPU Whisper without external API credentials. Inspect the real MP4/voice WAV, first/mobile frame, all subtitle cues, voice identity/EN-JA separation, pronunciation and ASR ambiguities, mix, meaning/translation and credits, plus quote scope and source rights. Evidence is written in `rights.md`, `render.mediaReview`, and `brief.deliveryReview`; the same 64-digit **MP4 SHA256** must be in all review records. Automated ASR/DSP is evidence, not human audition or legal clearance. Never mark unperformed checks complete. After a real review and the owner's permission, update the brief publication fields and ledger `stage: reviewed`, `gates.sourceText/sourceRights/ttsTerms/editorial/media: confirmed`, `blockers: []`, `ownerAuthorization.publicReleaseAuthorized:true` and a scope containing the exact clip ID.
4. **Release once:** on the owner-created tracking issue [#31](https://github.com/nomuonji/error-english/issues/31), the authenticated `nomuonji` owner posts `/aw-release aw-002-example-slug` (use the actual reviewed clip ID). ChatGPT's connected GitHub action can post this on the owner's behalf after completing the gates. Alternatively use **Actions → Annotated World delivery → Run workflow → release-reviewed**, with the `clip_id` field. The one workflow validates the source HEAD and episode-specific authorization, obtains the already-reviewed artifact, computes its actual SHA256, uploads **private** using the existing OAuth channel, persists its video ID and hash immediately as an issue comment and artifact, switches that **same** ID to public and polls YouTube `videos.list` until actual privacy becomes `public`.
5. **Report actual success only:** a public receipt with `videoId`, `privacy: public`, channel, SHA256, source SHA and readback timestamp is required. The agent records it in the source production ledger and checks the next CI; the error-english workflow cannot write directly to the source repository using its scoped `GITHUB_TOKEN`. Do not confuse an upload response, a public-switch request or a passed CI job with public-readback success.
6. **On interrupted release:** consult issue #31's private-upload checkpoint and Actions artifact/logs before retrying. The standard uploader searches the authenticated channel's upload playlist for `AW-CLIP:<clip-id>` and verifies `AW-SHA256:<digest>`; a matching existing ID is recovered instead of re-uploaded. A mismatch or uncertain upload status is a **stop condition** requiring diagnosis, not permission to insert a duplicate. The same owner release command is safe to retry only after verifying the existing video; never regenerate or send a second upload blindly. Already-`published` ledger entries are rejected by the preparation gate.

Only the source production ledger documents rights/editorial approval; issue comments and API-generated receipts are evidence of operational actions, not substitutes for review. Existing workflow_dispatch `verify`, `prepare` and `upload-private` remain for diagnostic/private-only use. Episode-001-only comment commands and scripts are historical and should not be used for new episodes.
