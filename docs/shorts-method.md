# ドパ英語 Shorts の作り方（method v1, 2026-11-18）

本人依頼「バズる動画を作るための研究 → 方法論に落とし込んで、コンテンツに反映」。
根拠は `analytics/experiments/competitor-research-2026-11-18.json`（Studio リサーチのブレイク動画約100本の一覧と、5本の再生フレーム分析）。
ここに書いたことは**検証前の仮説**で、当たったかどうかは公開後72時間の Shorts フィード流入で判断する（`analytics/experiments/`）。

## 前提：何で決まるか

- Shorts はまず少人数に見せ、見たかスワイプしたかで配信を広げるか決める。判断は最初の1〜3秒。
- 最後まで見られた割合も効く。長さより「最後まで見たくなる作り」。
- 2026-10 から YouTube は再アップロード（他人の映像の転載）の配信を減らす方針。切り抜き型は真似しない。

## 6つの仕組み（伸びている動画に共通していたもの）

| | 仕組み | 例 | うちでの扱い |
|---|---|---|---|
| M1 | **1本の中で何度も答えさせる**（穴あき＋3,2,1） | English Power「日本語では一言なのに英語だと詰まる8選」：約4秒ごとに1問 | 必須。`drill` で6〜8問 |
| M2 | **残りが見える**（一覧・TOP N・n/N を出しっぱなし） | Choka「それな」：①〜⑧が最初から画面にあり、タイトルの「それな」は⑤ | 必須。タイトル固定＋問題一覧＋カウンター |
| M3 | 人の顔・本物の会話 | ほぼ全本 | 未対応（自動化では作れない。本人の声・顔の導入は別途） |
| M4 | **前置きなし**。1秒目から1問目 | 全本 | 必須。0秒で1問目 |
| M5 | 比べる構図（学習者vsネイティブ、直訳vs自然） | Choka、もふログ | 推奨。`note` に「直訳×」「場面」を書く |
| M6 | 笑い・オチが主役 | ブリティッシュジョーク | 推奨。ラスト問題を一番意外・面白いものにする |

## 必須ルール（ゲートで機械的に検査）

- 形式は `drill`。1本に **6〜8問**。1問 = 日本語のお題 → 穴あき英語 → 3,2,1 → 答え（音声つき）。約4.8秒。
- **タイトル（pin）は動画の最初から最後まで画面上部に固定**。40字以内。
- **問題一覧を画面下に最初から全部出す**。今の問題を枠で、終わった問題を ✓ で示す。お題は12字以内。
- 右上に `n/N`、最後の問題は `LAST`。
- 最後は「何問わかった？」でコメントを促す（6 units）。
- skin は `poster` か `paper`。

## お題の選び方

1. **「言えそう」なのに出てこない**ものを選ぶ。簡単すぎ（Thank you）も難しすぎ（英検1級の難語）も外す。
   競合でも難語型は倍率が低かった。
2. 1本は**1つの切り口**でまとめ、タイトルでその切り口を約束する。
   - 日本語だと一言なのに英語で詰まる
   - 実は失礼に聞こえる英語 → 言い換え
   - 学校で習った言い方 vs ネイティブの言い方
   - 場面（会計・職場・病院・電話…）でとっさに必要な一言
   - 和製英語 → 本当の言い方
3. **ラスト問題は一番意外なもの**にし、タイトルかpinで「ラストが一番むずい」等と予告する（M2・M6）。
4. 穴にするのは**その表現の肝**の1語〜数語（key）。答えた瞬間に「それか！」となる位置。
5. `note` は答えの後に出る一言。「直訳×」「どんな場面か」「失礼になる理由」など、**へぇ**を足す（M5）。
6. 英語は自然さを辞書・用例で確認する。確信がない表現は使わない。既出の表現は台帳で弾かれる。

## やらないこと

- 1本1フレーズだけの動画（本人評価「内容が無い」）。
- 冒頭の挨拶・チャンネル名・「今日は〜を学びます」。
- 演出の派手さで中身を補うこと。
- 他人の映像・音声の転載。

## 次に検証すること

- drill（M1+M2+M4）で Shorts フィード流入が出るか。
- 出ない場合、M3（人の声・顔）が最大の差。本人に相談する。
